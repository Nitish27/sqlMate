# In-App Updates

SqlMate uses the Tauri updater with GitHub Releases as its distribution backend.
The app checks for updates five seconds after startup and also exposes a manual
check action in the toolbar and welcome screen. When an update is available, the
user can review the release notes, choose **Later**, or download and install it.

## GitHub Release assets

Each published release should contain:

- macOS `.dmg` and updater `.app.tar.gz` plus their `.sig` files
- Windows NSIS `.exe` and MSI installers plus their `.sig` files
- `latest.json`, generated by `tauri-apps/tauri-action`

The app reads the manifest from:

```text
https://github.com/Nitish27/sqlMate/releases/latest/download/latest.json
```

The repository and releases must be publicly accessible for this unauthenticated
endpoint to work.

## Signing key

The Tauri updater key is different from Apple or Windows code-signing keys. The
public key is committed in `src-tauri/tauri.conf.json`; the private key must never
be committed.

Generate a keypair once from the `sqlMate` directory:

```bash
npm run tauri -- signer generate -w /secure/path/sqlmate-updater.key
```

Add these repository secrets at **Settings → Secrets and variables → Actions**:

- `TAURI_SIGNING_PRIVATE_KEY`: the complete contents of `sqlmate-updater.key`
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: the password used when the key was generated

If the key is generated without a password, create the second secret with an empty
value. Keep a secure backup. Replacing the key later requires a coordinated update
because already-installed apps trust the public key embedded in their build.

## Release process

1. Update the version in `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`.
2. Commit and push the release changes.
3. Push a matching tag, for example `git tag v0.4.3 && git push origin v0.4.3`.
4. Wait for both macOS and Windows workflows to finish.
5. Confirm the draft release contains `latest.json`, signatures, and both platform installers.
6. Test the installers and updater flow on macOS and Windows.
7. Publish the GitHub release. The updater endpoint uses the latest **published** release, not a draft.

## Existing users

Builds before updater support cannot update themselves because they do not contain
the updater plugin, endpoint, or trusted public key. The first updater-enabled
release is therefore a one-time manual download. After users install that bridge
release, future published releases can be downloaded and installed in-app.

## Security notes

- Tauri verifies the updater signature before installation.
- GitHub Release assets are not a replacement for Windows Authenticode signing;
  unsigned Windows installers may still show a SmartScreen warning.
- Never put `TAURI_SIGNING_PRIVATE_KEY` in the repository, frontend bundle, release
  notes, or workflow logs.
